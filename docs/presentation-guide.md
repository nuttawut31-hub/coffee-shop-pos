## 2. โครงสร้างสไลด์นำเสนอ 10 สไลด์ (Slide Deck Outline)

- **Slide 1 (หน้าปก):** ชื่อโครงการ Coffee Shop POS System, รายวิชา 88734065 SAD, ชื่อทีม "ทีม 2 คนไทยออกมาบ่งชี้ ฝรั่งออกมาบ่งชู้", รายชื่อและรูปถ่ายสมาชิก 5 คน
- **Slide 2 (ปัญหาและที่มา - Background & Problem):** ปัญหาการจดออเดอร์ด้วยกระดาษ (จดผิด, ลืมตัวเลือกหวาน/ท็อปปิง, ส่งบาริสต้าล่าช้า, คิวมั่วช่วง Peak Hour)
- **Slide 3 (ความเป็นไปได้และแนวทางแก้ - Feasibility & To-Be BPMN):** การศึกษา TELOS, ระบบเว็บ POS สำหรับแคชเชียร์ + จอบาริสต้า (ลดเวลาสั่งเหลือ < 1 นาที คืนทุนใน 6-8 เดือน)
- **Slide 4 (ความต้องการของระบบ - Key Requirements):** Functional Requirements หลัก (FR-01 ถึง FR-08) เช่น การเลือกตัวเลือก, การคำนวณราคาอัตโนมัติ, การส่งคิวไปยังบาริสต้า
- **Slide 5 (Use Case & Flow):** Use Case Diagram สรุปความสัมพันธ์ของ Actor แคชเชียร์ และ บาริสต้า
- **Slide 6 (สถาปัตยกรรมระบบ BCM - System Architecture):**
  - **Boundary:** React SPA + Express Routes (`/api/products`, `/api/orders`)
  - **Control:** Controllers (`orderController.js`, `productController.js`)
  - **Entity:** Domain Models + SQLite Database (`cafe_pos.db`)
- **Slide 7 (Data Model & Class Diagram):** ความสัมพันธ์ของตารางฐานข้อมูล (`categories`, `products`, `product_options`, `orders`, `order_items`)
- **Slide 8 (ช่วง Live Demo):** สไลด์คั่นสำหรับสลับจอไปที่ระบบจริง (Live Demonstration)
- **Slide 9 (ผลการทดสอบ Usability & Testing):** ผ่าน 8/8 Test Cases, ผู้ใช้ทดสอบผ่าน 100%, คะแนน SUS 87.0 (Grade A)
- **Slide 10 (บทเรียนที่ได้รับและแนวทางพัฒนาต่อ - Lessons Learned):** ประสบการณ์การทำ BCM Architecture, การจัดการ Transaction ในฐานข้อมูล, และแนวทางต่อยอด (เช่น ระบบตัดสต็อกอัตโนมัติ FR-09)

## 3. สคริปต์ขั้นตอนการ Live Demo ระบบจริง (Step-by-Step Demo Script: 2–3 นาที)

> 💡 **เตรียมตัวก่อน Demo:**
>
> 1. รัน Backend ไว้ล่วงหน้า: ในโฟลเดอร์ `project/backend` รัน `npm start` (พอร์ต 3000)
> 2. เปิดหน้าเว็บ 2 หน้าต่างคู่กัน (หรือ 2 แท็บ):
>    - แท็บที่ 1: `http://localhost:3000` (หน้าจอ Cashier POS)
>    - แท็บที่ 2: `http://localhost:3000` สลับไปหน้าจอ Barista (หน้าจอคิวบาริสต้า)

### ขั้นตอนการสาธิตหน้าห้อง:

1. **เปิดหน้าจอ Cashier (0:00 - 0:30):**
   - _คำพูด:_ "นี่คือหน้าจอ POS ของพนักงานแคชเชียร์ครับ ด้านซ้ายแสดงเมนูแยกตามหมวดหมู่ กาแฟ ชา นม และเบเกอรี่ ดึงข้อมูลจากฐานข้อมูล SQLite ผ่าน REST API `/api/products`"
   - _การกระทำ:_ คลิกแท็บหมวดหมู่ Coffee, Tea เพื่อแสดงความลื่นไหลของการโหลดข้อมูล

2. **สั่งซื้อเครื่องดื่มพร้อมเลือก Option (0:30 - 1:15):**
   - _คำพูด:_ "เมื่อลูกค้าสั่งเครื่องดื่ม เช่น Iced Latte เราคลิกเลือก จะมี Option Modal ขึ้นมาให้เลือกขนาดแก้ว ระดับความหวาน และท็อปปิงเสริม โดยราคาจะคำนวณบวกเพิ่มทันที"
   - _การกระทำ:_ เลือกไซส์ Large (+10) + หวาน 50% + ท็อปปิงไข่มุก (+10) -> กด "เพิ่มลงตะกร้า"
   - _การกระทำต่อ:_ เลือกสินค้าเบเกอรี่เพิ่มอีก 1 ชิ้น เช่น ครัวซองต์ -> ปรับจำนวนเป็น 2 ชิ้น -> ชี้ให้เห็นว่ายอดสุทธิคำนวณอัตโนมัติ

3. **ชำระเงินและออกเลขคิว (1:15 - 1:45):**
   - _คำพูด:_ "เมื่อตรวจยอดถูกต้อง แคชเชียร์กดปุ่มชำระเงิน เลือกว่าเป็นเงินสดหรือ PromptPay QR กดยืนยัน ระบบจะทำ Transaction บันทึกข้อมูล และออกหมายเลขคิว เช่น A-001 พร้อมใบเสร็จ"
   - _การกระทำ:_ กดปุ่ม "ชำระเงิน" -> เลือก PromptPay -> กดยืนยัน -> แสดงหน้าต่างใบเสร็จและเลขคิว

4. **สลับไปหน้าจอบาริสต้า (1:45 - 2:20):**
   - _คำพูด:_ "ทันทีที่ออเดอร์เสร็จสิ้น ข้อมูลจะถูกส่งมายังหน้าจอของบาริสต้าแบบเรียลไทม์ โดยบาริสต้าจะเห็นเลขคิว รายการเครื่องดื่มพร้อมความหวานและท็อปปิงอย่างชัดเจน ไม่ต้องกลัวจดผิด"
   - _การกระทำ:_ ชี้ให้เห็นการ์ดคิวที่เพิ่งสั่งเข้ามา
   - _คำพูดต่อ:_ "เมื่อบาริสต้าเริ่มทำ จะกดปุ่ม 'เริ่มทำ' สถานะจะเปลี่ยนเป็น In Progress และเมื่อชงเสร็จ กด 'เสร็จสิ้น' คิวจะถูกเคลียร์ออก ถือเป็นการส่งมอบเครื่องดื่มสมบูรณ์ครับ"
   - _การกระทำ:_ กดปุ่มสถานะให้เห็นการเปลี่ยนแปลงสีและสถานะทันที

5. **สลับไปหน้าจอเจ้าของร้าน (Owner Dashboard & Menu Management) (2:20 - 2:50):**
   - _คำพูด:_ "ในมุมมองของเจ้าของร้าน (Owner View) เรามี 2 ฟังก์ชันหลักครับ คือ รายงานยอดขาย และ การจัดการเมนูสินค้า"
   - _การกระทำ 1:_ ชี้ให้เห็นแถบตัวเลือกสลับสาขา (Branch Switcher) ใน Navbar ซึ่งรองรับ 3 สาขา และสามารถกรองดูยอดขายเฉพาะสาขาได้แบบเรียลไทม์
   - _คำพูดต่อ:_ "และในแท็บ 'จัดการเมนูและราคาขาย' เจ้าของร้านสามารถเพิ่มเมนูใหม่ แก้ไขชื่อหรือราคา ลบเมนูที่ไม่ขายแล้ว และใส่ลิงก์รูปภาพพร้อมแสดงตัวอย่าง Live Preview ได้ทันทีครับ"
   - _การกระทำ 2:_ คลิกแท็บ 'จัดการเมนูและราคาขาย' ให้เห็นรายการเมนูและปุ่ม 'เพิ่มเมนูใหม่'

## 4. แนวทางการเตรียมตอบคำถามอาจารย์ (Anticipated Q&A)

| คำถามที่อาจารย์มักจะถาม                                                    | แนวทางการตอบที่ถูกต้องตามสถาปัตยกรรม                                                                                                                                                                                                                                       |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Q1: ทำไมถึงเลือกใช้ BCM Pattern แทน MVC ทั่วไป?**                        | **ตอบ:** BCM แบ่งหน้าที่ตามความรับผิดชอบชัดเจน โดย Boundary (`routes/views`) ดูแลการรับส่งข้อมูล, Control (`controllers/`) จัดการ Business Logic และ Validation, และ Entity (`entities/`) จัดการความถูกต้องของข้อมูล ทำให้แก้ไขหรือสลับฐานข้อมูลได้ง่ายโดยไม่กระทบส่วนอื่น |
| **Q2: หากอินเทอร์เน็ตขัดข้อง ระบบยังทำงานได้หรือไม่?**                     | **ตอบ:** ระบบนี้เป็น Monolithic ติดตั้งและรันบนเครื่อง Local ในร้าน พอร์ต 3000 เชื่อมกับ SQLite ในเครื่องเดียวกัน จึงสามารถทำงานออฟไลน์ได้ 100% แม้อินเทอร์เน็ตภายนอกจะหลุด                                                                                                |
| **Q3: ออเดอร์และรายการสินค้าย่อยจัดการเรื่องความสมบูรณ์ของข้อมูลอย่างไร?** | **ตอบ:** ใช้ Database Transaction ครอบการบันทึกตาราง `orders` และ `order_items` หากการบันทึกรายการใดล้มเหลว ระบบจะ Rollback ทั้งหมดเพื่อป้องกันข้อมูลตกหล่น                                                                                                                |
| **Q4: ระบบรองรับการจัดการหลายสาขา (Multi-Branch) อย่างไร?**                | **ตอบ:** เราออกแบบตาราง `branches` และมีฟิลด์ `branch_id` เชื่อมโยงในตาราง `orders` พร้อมทำตัวเลือกสลับสาขาใน Navbar ทำให้ทั้งการสั่งซื้อ การจัดคิวบาริสต้า และการดูสถิติยอดขายสามารถแยกตามสาขาได้อย่างเป็นเอกเทศครับ                                                   |
| **Q5: การจัดการเมนูและราคาของเจ้าของร้าน (FR-04) ปลอดภัยต่อประวัติการขายหรือไม่?** | **ตอบ:** การลบเมนูเราใช้เทคนิค Soft Delete (`is_active = 0`) ทำให้เมนูหายไปจากหน้าจอสั่งซื้อของแคชเชียร์ แต่ประวัติการขายและบิลเก่ายังคงมี Foreign Key ครบถ้วน ไม่ทำให้ข้อมูลใน `order_items` เสียหายครับ                                                          |
